# Omniverse Product Pulse

Use this skill to communicate state, release value, and risk clearly.

## Workflow

1. Gather recent changes, open work, blockers, metrics, and validation.
2. Separate shipped, in progress, blocked, and at-risk items.
3. Translate technical details into stakeholder-relevant outcomes.
4. For release materials, separate user-facing value from internal implementation.
5. Call out decisions, owners, rollout scope, limitations, or required user action.
6. Keep the update concise enough to read in one pass.

## Output Shape

- `Headline`
- `Shipped`
- `In progress`
- `Risks or blockers`
- `Decisions needed`
- `Next checkpoint`

## Rules

- Do not imply certainty where validation is incomplete.
- Do not overclaim beyond validated behavior.
- Include dates for deadlines, launches, or stale blockers.
- Prefer concrete status over activity lists.
